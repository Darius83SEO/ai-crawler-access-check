What each check measures
1
CCBot Access — Can AI crawlers physically reach the site? Reads robots.txt and tests the edge/WAF (CCBot user agent vs a browser) for blocks.
2
CC Index Coverage — Is the domain actually in the Common Crawl archive — how many pages, and how recently captured?
3
Harmonic Centrality — How close the domain sits to the web's core in the CC Web Graph. Central domains get crawled deeper and more often (it sets crawl priority).
4
Structured Data — Is key Schema.org markup (Organization, page, author, breadcrumb) in the server HTML, so models can represent and attribute the entity?
5
Server-Side Rendering — Does the content exist in the raw HTML without JavaScript? Many AI crawlers don't run JS, so JS-only content is invisible to them.
6
Agentic Readiness — A different question from the first five: can an autonomous AI agent (Operator, computer-use) navigate and act on the page? Reads the accessibility tree (semantic controls, roles, accessible names, heading hierarchy) and the presence + correctness of /llms.txt. Matters most for transactional journeys (buy, book, sign up).
Method. Six checks. Retrievability (1–5, most decisive first): (1) CCBot access — robots.txt + edge/WAF, (2) Common Crawl Index coverage, (3) Harmonic Centrality in the CC Web Graph, (4) Schema.org structured data, (5) server-side rendering. The old world was index & rank; the new world is train & retrieve — if you're not in the crawl, you're not in the model. Agentic readiness (6): can an autonomous AI agent navigate and act on the page — accessibility tree + llms.txt. Centrality data via the community CC Rank Checker (webgraph.metehan.ai); verify single data points against official sources where a decision hinges on them.
